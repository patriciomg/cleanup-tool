# Releasing

The tag-triggered workflow in [`.github/workflows/release.yml`](../.github/workflows/release.yml) builds, signs, and publishes a GitHub Release whenever a `v*` tag is pushed.

> **Note:** `make release` must be run on macOS because the universal binary is created with `lipo`.

## Local release artifacts

```bash
# Build the universal binary, tarball, and checksums locally
cd cleanup-tool
make release

# Sign the artifacts with GPG (requires a configured GPG key).
# Optional: use GPG_KEY_ID to select a specific key.
make release-sign
# or: GPG_KEY_ID=YOUR_KEY_ID make release-sign

# Verify a signature
gpg --verify dist/checksums.txt.asc dist/checksums.txt
gpg --verify dist/cleanup-tool-<version>-darwin-universal.tar.gz.asc \
            dist/cleanup-tool-<version>-darwin-universal.tar.gz
```

## Publishing a release from GitHub Actions

1. **Generate a GPG key** (if you do not already have one):

   ```bash
   gpg --full-generate-key
   # Choose a secure key type, e.g., ED25519 or RSA/RSA 4096 bits.
   ```

2. **Export the private key** for GitHub Actions:

   ```bash
   gpg --list-secret-keys --keyid-format LONG
   # Use the long key ID from the output above
   gpg --armor --export-secret-keys <KEY_ID> > cleanup-tool-release.asc
   ```

3. **Add the secrets to your repository** on GitHub under **Settings → Secrets and variables → Actions**:

   - `GPG_PRIVATE_KEY` (required for signing): the contents of `cleanup-tool-release.asc`
   - `GPG_PASSPHRASE` (only if your key has a passphrase): the passphrase for that key
   - `GPG_KEY_ID` (optional): the long key ID or fingerprint to use if you have multiple signing keys

   If `GPG_PRIVATE_KEY` is not set, the workflow will still publish a release, but the assets will not be signed.

4. **Push a version tag** (`v*`):

   ```bash
   git tag -a v1.0.0 -m "Release v1.0.0"
   git push origin v1.0.0
   ```

5. The `release` workflow will:

   - Run tests and `go vet` on `macos-latest`
   - Build `cleanup-tool-darwin-universal` and the release tarball
   - Generate `checksums.txt`
   - Import the GPG key and run `make release-sign`
   - Verify the signatures
   - Create the GitHub Release and upload the tarball, checksum file, and `.asc` signatures

## Homebrew formula

The Homebrew formula lives in a dedicated tap repository at [`patriciomg/homebrew-cleanup-tool`](https://github.com/patriciomg/homebrew-cleanup-tool). The release workflow automatically updates the formula's `url` and `sha256` in that repository after a release is published, so no manual editing is required for normal releases.

Users can install or update the tool via Homebrew:

```bash
brew install patriciomg/cleanup-tool/cleanup-tool
```

Homebrew 4.1+ may ask users to trust the tap first. For the latest install and trust instructions, see the [README.md](../README.md#install-with-homebrew-recommended).

> **Required:** The auto-bump step pushes to the `patriciomg/homebrew-cleanup-tool` repository. The default `GITHUB_TOKEN` is scoped only to the current repository and will be rejected with a 403 error, so the workflow uses a dedicated secret named `TAP_GITHUB_TOKEN` instead. If the secret is missing or empty, the workflow fails fast at the `Update Homebrew formula` step with a clear error message — the GitHub Release itself is already published at that point, but the formula step fails and the workflow run is reported as failed.

### Creating and rotating the `TAP_GITHUB_TOKEN` secret

**1. Create a Personal Access Token** (needs your GitHub login/2FA — it cannot be generated by CI):

- **Fine-grained token (recommended, least privilege):**
  - Repository access: *Only select repositories* → `patriciomg/homebrew-cleanup-tool`
  - Permissions → **Contents:** *Read and write*
  - Copy the resulting `github_pat_...` value immediately (shown only once).
- **Classic token:** select the **`repo`** scope and copy the `ghp_...` value.

**2. Add it as a repository secret:**

- Web UI: open https://github.com/patriciomg/cleanup-tool/settings/secrets/actions → **New repository secret** → Name `TAP_GITHUB_TOKEN`, paste the token, save.
- Or via the CLI: `gh secret set TAP_GITHUB_TOKEN --repo patriciomg/cleanup-tool --body <token>`

**3. Verify it is stored:**

```bash
gh secret list --repo patriciomg/cleanup-tool
# should list: TAP_GITHUB_TOKEN   Updated <date>
```

**4. Rotate the token when needed** (e.g., it expired, or you suspect it leaked):

1. Create a new PAT (same steps as above).
2. Update the secret with the new value (same steps as adding it).
3. **Revoke the old token** at https://github.com/settings/tokens so it stops working.
4. Push a new `v*` tag to confirm the bump succeeds with the new token. (Re-running the whole release job for an already-published tag is not recommended — the `Publish GitHub Release` step errors when a release for that tag already exists; re-run only the `Update Homebrew formula` step if you want to retry it in place.)

The workflow reads the secret fresh on every run, so rotation takes effect immediately — no code or workflow changes are required.

**Manual fallback:** if the secret is missing or expired and you cannot set it right away, you can still bump the formula by hand: clone `patriciomg/homebrew-cleanup-tool`, update the formula's `url` and `sha256` (from the release tarball's `checksums.txt`), commit, and push. See [the dry-run script](#testing-the-formula-bump-locally) for a local preview of the same steps.

### Homebrew tap trust

Homebrew 4.1+ treats third-party taps as untrusted by default and may refuse to install from them until the user explicitly trusts the tap or the specific formula. This is a Homebrew client-side security feature; the formula itself does not need to do anything special.

Trust the tap before installing:

```bash
brew trust patriciomg/cleanup-tool
brew install patriciomg/cleanup-tool/cleanup-tool
```

For the latest install instructions, including how to handle tap-trust prompts, see the [README.md](../README.md#install-with-homebrew-recommended).

### Testing the formula bump locally

You can dry-run the release tarball build and formula auto-bump without publishing anything:

```bash
./scripts/dry-run-formula-bump.sh [VERSION]
```

The script builds a local release tarball, updates `Formula/cleanup-tool.rb` with a local `file://` URL, runs `brew audit --new`, and restores the original formula afterwards.

## Verifying a published release

```bash
# Download the public key from the release author and import it
gpg --import <author-public-key.asc>

# Verify the checksum file signature
gpg --verify checksums.txt.asc checksums.txt

# Verify the tarball signature
gpg --verify cleanup-tool-<version>-darwin-universal.tar.gz.asc \
            cleanup-tool-<version>-darwin-universal.tar.gz
```
